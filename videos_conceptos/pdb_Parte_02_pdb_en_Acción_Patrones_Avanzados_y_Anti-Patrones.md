Ya conocemos la teoría, pero ¿cómo se ve un detective de código en acción? Vamos a resolver un bug real, paso a paso, y a descubrir los patrones que separan a un programador junior de un maestro de la depuración.

# pdb

### 4. Implementación Práctica: Del Caos a la Maestría

Vamos a resolver un problema real. Tenemos una función que calcula el factorial, pero contiene un error sutil que solo aparece con ciertos valores.

**El Código Defectuoso (`factorial_bug.py`):**
```python
# factorial_bug.py

def factorial(n):
    """Calcula el factorial de n, con un bug sutil."""
    if n < 0:
        raise ValueError("El factorial no está definido para números negativos")
    
    # Bug: La inicialización debería ser 1, no 0.
    # Un error fácil de pasar por alto en una revisión de código.
    resultado = 0 
    
    for i in range(1, n + 1):
        # En la primera iteración, resultado se vuelve 0 * 1 = 0
        # y nunca se recupera.
        resultado *= i
        
    return resultado

if __name__ == "__main__":
    numero = 5
    print(f"El factorial de {numero} es {factorial(numero)}")
```
Al ejecutarlo, obtenemos `El factorial de 5 es 0`, lo cual es incorrecto.

#### Patrón 1: Depuración Post-Mortem (El Forense Digital)

Nuestro script falla con una excepción si le pasamos un número negativo. ¿Cómo inspeccionar el estado *justo en el momento del crash*?

Modifiquemos el código para usar `pdb.pm()`:
```python
# ... (código de factorial)
import pdb
import sys

def main():
    try:
        numero = -5
        print(f"El factorial de {numero} es {factorial(numero)}")
    except Exception:
        # Obtiene la información de la excepción
        exc_type, exc_value, exc_traceback = sys.exc_info()
        print(f"💥 Ocurrió un error: {exc_value}")
        print("Iniciando depuración post-mortem...")
        pdb.pm() # ¡La magia!

if __name__ == "__main__":
    main()
```

Al ejecutarlo, el programa se detiene *después* del `ValueError` y nos deja en el depurador, justo en la línea que lanzó la excepción.

```bash
$ python factorial_bug.py
💥 Ocurrió un error: El factorial no está definido para números negativos
Iniciando depuración post-mortem...
> /path/to/factorial_bug.py(6)factorial()
-> raise ValueError("El factorial no está definido para números negativos")
(Pdb) 
```
Ahora podemos inspeccionar.
-   `(Pdb) p n`: Imprimirá `-5`.
-   `(Pdb) where`: Nos mostrará la pila de llamadas completa.
-   `(Pdb) up`: Nos moverá al frame de `main()` para ver qué valor tenía `numero` allí.

#### Patrón 2: Puntos de Interrupción Estratégicos (El Francotirador)

Volvamos al bug original (resultado `0`). No hay excepción. Simplemente el resultado es incorrecto. Sospechamos que algo va mal dentro del bucle `for`.

Insertamos `pdb.set_trace()` como un punto de interrupción.

```python
# factorial_bug.py
import pdb

def factorial(n):
    # ... (código anterior)
    resultado = 0 
    
    for i in range(1, n + 1):
        pdb.set_trace() # <-- PUNTO DE INTERRUPCIÓN
        resultado *= i
        
    return resultado

if __name__ == "__main__":
    numero = 5
    print(f"El factorial de {numero} es {factorial(numero)}")
```

Ahora, al ejecutar, el programa se detendrá en la primera iteración del bucle.

```bash
$ python factorial_bug.py
> /path/to/factorial_bug.py(14)factorial()
-> resultado *= i
(Pdb) 
```

Nuestra sesión de depuración podría ser así:
1.  **Inspeccionar estado inicial:**
    -   `(Pdb) p resultado` -> `0`
    -   `(Pdb) p i` -> `1`
    -   *Aha! `resultado` es 0. `0 * 1` será `0`. Aquí está el problema.*
2.  **Confirmar la hipótesis:**
    -   `(Pdb) n` (ejecuta `resultado *= i`)
    -   `(Pdb) p resultado` -> `0`
    -   *Confirmado. El resultado nunca dejará de ser 0.*
3.  **Probar la solución en caliente:**
    -   `(Pdb) resultado = 1` (¡Podemos cambiar variables!)
    -   `(Pdb) c` (continúa la ejecución hasta el siguiente punto de interrupción)
4.  **Segunda iteración:**
    -   El programa se detiene de nuevo.
    -   `(Pdb) p resultado` -> `1` (el valor que le dimos)
    -   `(Pdb) p i` -> `2`
    -   `(Pdb) n`
    -   `(Pdb) p resultado` -> `2`
    -   *¡Ahora funciona!*
5.  **Salir:**
    -   `(Pdb) q`

Hemos encontrado y verificado la solución sin tener que editar y re-ejecutar el código múltiples veces.

### 5. Nivel Senior - Conceptos Avanzados

Aquí es donde separamos a los aprendices de los maestros. Un senior no solo usa la herramienta, sino que entiende su lugar en el ecosistema y sus implicaciones.

#### Trade-offs: El Arsenal del Depurador

No existe una bala de plata. Un desarrollador senior elige la herramienta adecuada para cada situación.

| Herramienta        | Cuándo Usarlo                                                                | Ventajas                                                              | Desventajas                                                            |
|--------------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------|------------------------------------------------------------------------|
| **`pdb` / `ipdb`** | Depuración en servidores, contenedores, CI/CD, o cuando se prefiere el teclado. | Ligero, universal, potente, no requiere GUI, control granular.        | Curva de aprendizaje, menos visual, puede ser lento.                   |
| **IDE Debugger**   | Desarrollo local, exploración visual de estructuras de datos complejas.      | Muy visual, fácil de usar, integración con el editor.                 | Pesado, atado a un IDE, puede ocultar la mecánica subyacente.          |
| **Logging**        | Rastrear eventos en producción, análisis post-mortem de sistemas de larga duración. | Persistente, bajo overhead (si se configura bien), estándar de la industria. | No es interactivo, requiere planificación previa (saber qué loguear). |
| **`print()`**      | Para la verificación más rápida y sucia de un solo valor en un script simple. | Rápido y fácil para casos triviales.                                  | Desordenado, no interactivo, se olvida fácilmente en el código.        |

La decisión de usar `pdb` es una decisión de diseño: priorizo la portabilidad y el control interactivo sobre la comodidad visual.

#### Anti-Patrones: Las Trampas del Oficio

-   **El `set_trace()` Olvidado:** El pecado capital. Hacer commit de un `pdb.set_trace()` a una rama principal puede detener la ejecución en producción o en los tests de CI. Usa hooks de pre-commit para buscar y advertir sobre esto.
-   **Depuración como Sustituto del Pensamiento:** Si pasas horas en `pdb` para una función simple, quizás el problema es el diseño. Un código más simple, más puro (funciones sin efectos secundarios) y bien probado a menudo elimina la necesidad de una depuración extensiva.
    > "La forma más efectiva de depuración es evitar los errores en primer lugar." — **Brian W. Kernighan**, *The Practice of Programming* (1999)
-   **Ignorar la Pila (`where`):** Un error común es enfocarse solo en las variables locales. A menudo, el bug se origina en la función que llamó a la actual. Usa `up` y `down` para viajar en el tiempo a través de la pila y entender el contexto completo.
-   **El "Heisenbug":** Un bug que desaparece o cambia cuando intentas observarlo. `pdb`, al ralentizar drásticamente la ejecución, puede alterar las condiciones de carrera (race conditions) u otros problemas de temporización. En estos casos, el logging es a menudo una mejor herramienta.

#### Integración y Ecosistema

-   **`ipdb` es tu mejor amigo:** `pip install ipdb`. Úsalo en lugar de `pdb`. El autocompletado por sí solo vale la pena. `import ipdb; ipdb.set_trace()`.
-   **Depuración Remota con `rpdb`:** Instala `rpdb` en un servidor. En tu código, añade `import rpdb; rpdb.Rpdb(addr='0.0.0.0', port=4444).set_trace()`. El proceso se detendrá. Desde tu máquina local, puedes conectarte con `telnet <ip_servidor> 4444` y obtener una sesión de `pdb` completa. Revolucionario para depurar demonios o aplicaciones web en su entorno real.
-   **Puntos de Interrupción Condicionales:** `pdb` lo soporta. Después de `b <numero_linea>`, puedes usar `condition <breakpoint_id> <expresion>`. Por ejemplo, `condition 1 i == 500`. El depurador solo se detendrá en ese punto si `i` es 500. Esto es increíblemente útil para bucles largos.
